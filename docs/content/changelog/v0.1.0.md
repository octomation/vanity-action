# v0.1.0 — Publish the module with its release.

The first release. A Go module's release workflow publishes the module to
[octolab/vanity](https://github.com/octolab/vanity), the catalog behind
`go.octolab.org`: one entry `modules/<module path>.json` instead of a
submodule and a hand-edited manifest.

## Publish from a module

```yaml
- name: Publish the module to go.octolab.org
  uses: octomation/vanity-action@v0.1.0
  with:
    token: ${{ steps.catalog.outputs.token }}
    packages: all
```

The README has the whole job: a credentials check that warns and ends green
where the Releaser secrets are not available, the checkout, Go and the
catalog token.

- Writes the entry in one commit signed by the token's GitHub App,
  `chore(<name>): publish vX.Y.Z`, and tags it `<name>--vX.Y.Z`; `name` is
  the repository name unless the input sets it, and may have segments, as
  `ecosystem/tablo`.
- Accepts only an annotated `vX.Y.Z` tag that GitHub verifies, on the checked
  out commit, whose major version matches the module path; a prerelease ends
  green with a notice. Only a module with `go.mod` at the repository root.
- Lists the packages from the commit's tracked files, whatever the runner's
  GOOS, GOARCH or cgo: a package behind a build tag is listed too.
  `packages: auto` publishes the root only of a private or internal
  repository; `all` and `root` choose explicitly.
- A published release is frozen. Running it again is safe: a retry is a
  no-op even when the repository's topics or branch changed, a missing
  catalog tag is repaired, an older version that never reached the catalog
  is a no-op, and a concurrent publication of another module is retried.
- A project generated from a template keeps a green release: a module path
  outside `go.octolab.org`, or still the template's own, is skipped with a
  warning.
- Refuses before writing what the catalog would reject: an invalid entry, a
  package of two modules, a page rendered over another module's package, a
  name of two modules.
- `dry-run: true` decides and logs the entry without writing.
- Outputs `decision`, `changed`, `catalog-commit`, `catalog-tag`, `module`,
  `name` and `entry-path`, and a step summary; a publication adds how many
  modules of the catalog publish themselves and which are still seeds.

## For catalog maintainers

```bash
npx --yes github:octomation/vanity-action#v0.1.0 entry --path . --packages all
```

prints the canonical entry of a checkout or a plain directory.
